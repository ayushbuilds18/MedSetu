# MedSetu — PostgreSQL + Admin Dashboard Edition

MedSetu is an educational medicine-information prototype. **It informs; it never prescribes.** The bundled catalogue contains illustrative demo data; prices and manufacturer names are fictional. Kendra records must be verified before being presented as real locations.

## Features
- FastAPI website and API
- PostgreSQL on hosting; SQLite fallback for local development
- 40-record illustrative catalogue imported on first startup
- Admin dashboard at `/admin` to add, edit and delete catalogue medicines and Kendra records
- Admin sessions use signed, HttpOnly, SameSite=Strict cookies
- Admin credentials and signing secret are supplied through environment variables, never committed to Git

## Run locally on Windows (PowerShell)
From this folder:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
$env:MEDSETU_ADMIN_USERNAME = "admin"
$env:MEDSETU_ADMIN_PASSWORD = "Use-A-Strong-Unique-Password-Here"
$env:APP_SECRET = "replace-this-with-a-long-random-secret"
$env:COOKIE_SECURE = "false"
py -m uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000` for the public website and `http://127.0.0.1:8000/admin` for the admin dashboard. Change the sample password before use. Do not use a real password from another account.

## Deploy to Render with PostgreSQL
1. Upload the contents of this project folder to the root of a GitHub repository. Do not upload `.venv`, `.env`, or local database files.
2. In Render, choose **New → Blueprint** and connect the GitHub repository. Render reads `render.yaml` and defines a web service plus PostgreSQL.
3. When prompted for `MEDSETU_ADMIN_USERNAME` and `MEDSETU_ADMIN_PASSWORD`, enter a new username and a strong, unique password. Never put these values in GitHub or in `render.yaml`. `APP_SECRET` is generated by Render.
4. Deploy. Open the generated Render URL, then append `/admin` to access the dashboard.
5. Test `/health`, public medicine search, admin login, adding a test record, and confirming it remains after a redeploy.

### Important free-tier warning
The Blueprint currently uses Render's free plans to make a low-cost demo possible. Render's free Postgres databases expire 30 days after creation, have no backups, and are not suitable for long-term data storage. Upgrade the database to a paid plan before the expiry date if you need to keep records. The free web service may spin down when idle. Check current Render pricing and limits before deployment.

## Changing data after deployment
Sign in at `/admin`. Add, edit, or delete medicine catalogue rows and Kendra rows. Changes are written directly to PostgreSQL and do not require a code redeploy. Code or frontend changes still require a new deployment.

## Data safety and clinical limitations
- Bundled prices and manufacturer values are fictional demo values and must stay labelled `DEMO_ONLY`.
- Do not mark clinical equivalence based on name or price. The app does not provide prescribing advice.
- Only mark Kendra records verified after checking a trustworthy source. No live PMBI directory, geocoding, opening-hours or stock feed is connected.
- Do not store patient records, prescriptions, diagnoses, or other sensitive health information in this prototype.
- Back up the database before bulk edits or deletion.

Add verified records through the protected admin dashboard or populate the CSV using confirmed source data.
